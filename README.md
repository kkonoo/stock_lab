# 📈 주식 연습장

조건식으로 사고 익절·손절 규칙으로 파는 전략을 과거 데이터로 돌려 보는 공부용 웹 앱이에요.
실제 주문 기능은 없어요. **학습용이며 투자 권유가 아니에요.**

## 앱 열기

- **GitHub Pages**: 저장소 Settings → Pages → Build and deployment에서 Source를 **Deploy from a branch**, Branch를 기본 브랜치와 `/ (root)`로 고르고 Save를 눌러요.
  몇 분 뒤 `https://kkonoo.github.io/stock_lab/`에서 열려요.
- **내 컴퓨터**: `index.html`을 더블클릭하면 시세 파일을 못 읽어요(브라우저가 `file://`에서 fetch를 막음). 대신 PowerShell에서
  `powershell -ExecutionPolicy Bypass -File tools/serve.ps1`을 실행하고 http://localhost:8767/ 을 열어요.
- 폰에서 **홈 화면에 추가**하면 앱처럼 열려요. 한 번 열어 둔 뒤에는 인터넷이 없어도 마지막으로 받은 시세로 열려요.
- 전략·설정은 이 브라우저(localStorage)에만 저장돼요. 다른 기기로 옮길 때는 📤 내보내기 → 📥 불러오기를 써요.

## 쓰는 법

1. **🇰🇷 국내 / 🇺🇸 미국**을 골라요. 원화와 달러를 섞지 않게 시장마다 따로 돌려요.
2. **🧪 전략**에서 `＋ 새 전략`을 누르거나 예시 전략의 `✏️ 고치기`를 눌러요.
   - 🛒 **언제 살까요?** `＋ 조건 추가`로 조건을 더해요. 모두 만족한 날(종가 기준) 다음 날 시가에 사요.
     조건: 종가 vs 이동평균 · 골든크로스/데드크로스 · RSI · 최근 n일 수익률 · 거래량 급증 · 52주 신고가 근처
   - 💰 **언제 팔까요?** 익절 +x% · 손절 −y% · 최대 보유일(비우면 안 씀)
   - 👛 **돈은 얼마나?** 시작 자본 · 1회 매수(고정 금액 또는 총자산의 %) · 최대 동시 보유 종목 수
   - 고치면 바로 저장돼요.
3. **📊 결과**: 지표 카드, 자산 곡선 vs 벤치마크, 거래 목록. 거래를 누르면 그 종목 캔들 차트에 ▲매수 ▼매도가 보여요.
   위쪽에서 기간(전체·5년·3년·1년·직접)을 바꿀 수 있어요.
4. **⚖️ 비교**: 전략을 골라 지표를 나란히 보고 누적 수익률을 겹쳐 봐요.
5. **⚙️ 설정**: 시장별 수수료·세금·슬리피지(%)와 테마. 넣어 둔 비용은 예시값이라 실제 요율로 고쳐 주세요(`js/config.js`의 기본값).
6. **📁 데이터**: 종목별 데이터 첫날·마지막 날. 다른 종목보다 늦으면 ⚠️ (수집 실패 의심 → Actions 로그 확인).
7. **📤 내보내기 / 📥 불러오기**: 국내·미국 전략을 JSON 파일 하나로 저장하고, 불러오면 지금 전략에 더해요(덮어쓰지 않음).
8. **📖 공부**: 주식 기초·차트 지표·스윙매매·결과 읽는 법·장기투자·가치투자 용어집이에요. 화면 곳곳의 **ⓘ**를 누르면 그 용어 설명으로 바로 가요.

> 관심 종목 안에서만 돌리기 때문에 **생존 편향**이 있어요. 지금까지 살아남은 종목을 골랐으니 과거 결과가 실제보다 좋게 나오기 쉬워요.

## 용어 추가하는 법

`data/glossary.json`을 GitHub에서 열고 ✏️ Edit → `terms` 목록에 하나를 더해요(앞 항목 끝에 쉼표).

```json
{
  "id": "vix", "cat": "long", "term": "VIX (공포지수)", "aka": "변동성지수",
  "short": "한 줄 설명",
  "body": ["문단 1", "문단 2"],
  "example": "예시 (없어도 돼요)",
  "see": ["sp500", "mdd"]
}
```

- `id`: 영어 소문자·숫자·하이픈, 겹치지 않게 · `cat`: `basic` `chart` `swing` `result` `long` `value` 중 하나
- `aka`: 검색에 걸릴 다른 이름(띄어쓰기로 여러 개) · `see`: 함께 볼 용어의 `id`
- 글자만 써요(HTML·마크다운은 그대로 글자로 보여요). 저장하면 Pages가 다시 배포된 뒤 앱에 보여요.

## 시세 데이터

GitHub Actions가 매일 관심 종목의 일봉(수정주가)을 받아서 `data/`에 저장해요. 앱은 이 파일만 읽어요.

| 파일 | 내용 |
|---|---|
| `data/watchlist.json` | ✏️ 관심 종목 목록 (직접 고치는 파일) |
| `data/prices/kr/{티커}.json`, `data/prices/us/{티커}.json` | 🤖 종목별 일봉 (날짜·시가·고가·저가·종가·거래량) |
| `data/meta.json` | 🤖 종목별 데이터 첫날·마지막 날 |

### 관심 종목 추가하는 법

1. GitHub에서 `data/watchlist.json`을 열고 연필(✏️ Edit) 버튼을 눌러요.
2. `stocks` 목록에 한 줄을 넣어요. 앞 줄 끝에 쉼표(`,`)를 잊지 마세요.
   ```json
   { "ticker": "035720", "name": "카카오" }
   ```
   - **국내**: 6자리 종목코드를 **따옴표로 감싸서** 써요 (`"035720"`). 따옴표가 없으면 앞의 0이 사라져요. 코스피·코스닥 구분은 필요 없어요.
   - **미국**: 야후 파이낸스 티커를 써요 (`"TSLA"`, 점 대신 하이픈: `"BRK-B"`).
3. Commit changes를 눌러 저장해요.
4. 저장(커밋)하면 Actions가 바로 돌아서 새 종목의 최근 10년치를 받아요. 몇 분 뒤 `data/prices/`에 파일이 생겨요.

- 벤치마크는 `benchmark` 칸이에요 (국내 KODEX 200, 미국 SPY).
- 목록에서 지워도 가격 파일은 남겨 둬요. 다시 넣으면 이어서 받아요. 앱은 목록에 있는 종목만 써요.
- 쉼표나 따옴표가 틀려서 JSON 형식이 깨지면 실행이 ❌ 실패하고 로그에 몇 번째 줄인지 나와요.

### Actions 수동 실행하는 법

1. 저장소 위쪽 **Actions** 탭 → 왼쪽에서 **시세 업데이트**를 골라요.
2. 오른쪽 **Run workflow** 버튼 → 받을 시장(`all` / `kr` / `us`)을 고르고 초록 **Run workflow**를 눌러요.
3. 끝나면 실행을 눌러 **Summary**에서 결과 표(새로 받음·덧붙임·실패 목록)를 볼 수 있어요.

### 자동 실행 시간

| 시장 | 시간 (한국) | cron (UTC) |
|---|---|---|
| 국내 | 월~금 16:30 | `30 7 * * 1-5` |
| 미국 | 화~토 07:07 (뉴욕 장 마감 1~2시간 뒤) | `7 22 * * 1-5` |

`data/watchlist.json`이나 수집 코드(`scripts/`, 워크플로 파일)를 고쳐서 커밋해도 바로 한 번 돌아요(국내·미국 전부).

- GitHub 스케줄은 붐비면 수십 분 늦게 돌기도 해요.
- 휴장일에도 돌지만 새 데이터가 없으면 커밋하지 않아요.
- 스케줄은 기본 브랜치에서만 돌아요.

### 받는 방식

- **새 종목**: 최근 10년치를 받아요.
- **이미 있는 종목**: 최근 10거래일을 겹쳐 받아 비교해요.
  - 겹친 날 종가가 그대로면 → 새 날짜만 덧붙여요.
  - 달라졌으면 → 분할·배당으로 과거 수정주가가 바뀐 거라 그 종목만 처음부터 다시 받아요.
    (새 날짜만 붙이면 그 지점에 가짜 급등락이 생기거든요.)
- **실패**: 한 종목이 실패해도 기존 파일은 그대로 두고 나머지를 계속 받아요. 실패 목록은 로그와 Summary에 남아요.
  - 일부만 실패 → ⚠️ 경고만 남기고 받은 건 커밋해요.
  - 한 시장을 통째로 못 받음 → 받은 건 커밋하고 실행을 ❌ 실패로 표시해요. GitHub이 메일로 알려 줘요.

### ⚠️ 데이터 출처 주의

- **pykrx(국내)와 yfinance(미국)는 공식 API가 아니에요.** 네이버·야후 웹 데이터를 가져오는 방식이라 사이트가 바뀌면 가끔 깨져요.
  깨지면 실행이 실패로 표시되니, 라이브러리 새 버전이 나왔는지 확인하고 `scripts/requirements.txt`의 버전을 올려 보세요.
- yfinance는 GitHub 서버에서 요청이 많으면 잠깐 막힐 때(rate limit)가 있어요. 다음 실행에서 보통 풀려요.
- 로그에 `KRX 로그인 실패: KRX_ID 또는 KRX_PW ...`가 보여도 괜찮아요. 수정주가는 네이버 경로로 받아서 KRX 로그인이 필요 없어요.
- **국내 수정주가는 분할·병합·증자만 반영하고 배당은 빠져 있어요.** 미국은 분할과 배당이 모두 반영돼요.
  국내 결과는 "배당 없는 가격 수익률"이에요. 전략과 벤치마크(KODEX 200)가 같은 기준이라 둘을 비교하는 건 괜찮아요.

## 백테스트 규칙 (js/engine.js)

| 항목 | 규칙 |
|---|---|
| 매수 | t일 종가 기준으로 조건을 모두 만족하면(AND) **t+1일 시가**에 매수. 마지막 날 신호는 거래 안 함 |
| 익절·손절 기준가 | 실제 매수 체결가(슬리피지 포함)에서 +x% / −y% |
| 같은 날 익절가·손절가 둘 다 닿음 | 일봉으론 순서를 모르니 **손절**로 처리 (보수적) |
| 갭 | 시가가 이미 손절가 아래·익절가 위로 시작하면 **시가**에 매도 |
| 매수한 날 | 시가에 산 뒤 그날 고가·저가로 바로 익절·손절될 수 있음 |
| 최대 보유일 | 거래일 기준, 매수일을 1일째로 세서 n일째 종가에 매도 (⏰ 기간만료) |
| 동시 보유 | 최대 n종목. 같은 날 신호가 빈 자리보다 많으면 관심 종목 목록 순서대로, 나머지는 무시 |
| 같은 종목 | 보유 중이면 다시 사지 않음 |
| 매도로 생긴 현금·빈 자리 | 다음 날부터 사용 |
| 1회 매수 금액 | 고정 금액 또는 전날 총자산(현금 + 보유 종목 평가액)의 % — 정수 주만, 현금이 모자라면 건너뜀 |
| 비용 | 매수가 = 시가 × (1 + 슬리피지), 매도가 = 가격 × (1 − 슬리피지). 수수료는 사고팔 때 둘 다, 세금은 팔 때만 |
| 끝날 때 보유 중 | 마지막 종가로 평가만 (📌 보유 중). 승률·거래 횟수에선 빠짐 |
| 벤치마크 | 시작일 종가에 초기 자본 전부 사서 보유, 비용 없음 |
| 지표 | 이동평균 = 오늘 포함 n일 단순평균 · RSI = Wilder 방식 · 거래량 평균 = 오늘 뺀 직전 n일 · 52주 신고가 = 오늘 포함 252거래일 고가 중 최고 |

### 엔진 테스트

`test.html`을 브라우저로 열면(파일을 더블클릭해도 돼요) 합성 데이터로 만든 테스트 결과가 나와요.
엔진(`js/engine.js`)을 고쳤으면 이 페이지가 ✅ 모두 통과인지 확인해 주세요.

